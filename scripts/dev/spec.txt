⚠ ROOT CAUSE — CRITICAL BUG
BridgeManager.initializeBridge() calls security.initiateBiometricHandshake() (WebAuthn/Face ID/Touch ID) BEFORE every bridge auth flow. This native passkey modal fires on every Connect button click — overriding and replacing the platform-correct auth flow (OAUTH2, TOKEN, QR_SYNC, SECURE_TUNNEL, or WEB_SESSION) that should be shown instead.

After the biometric check, AuthPortal.handleAuth() calls setTimeout() to fake a 'verification' for every non-Verus bridge — meaning NONE of the 20 bridges perform any real credential exchange. Every bridge appears to connect in 2 seconds but stores nothing in the vault and activates no adapter.

WebAuthn/Face ID belongs ONLY to Alluci app login. It has zero role in bridge credential collection.

Architecture Principle — Bridge Auth vs App Login
Separation of Concerns
initiateBiometricHandshake() / WebAuthn / Face ID / Touch ID:
  → Belongs exclusively to: Alluci daemon LOGIN (/auth/webauthn/* endpoints)
  → Must NEVER appear in: bridge credential collection

Bridge credential auth is a different concern entirely:
  → It collects platform-specific tokens (Telegram), OAuth tokens (Slack), QR pairings (WhatsApp), macOS permissions (iMessage), or browser sessions (WebChat)
  → It POSTs those credentials to /api/channels/{id}/config (vault storage)
  → It calls /api/channels/{id}/connect (adapter activation)
  → The user identity for THIS STEP is already established by the Alluci JWT session token

FIX-05 — New shared helper: src/lib/bridgeAuth.ts
src/lib/bridgeAuth.ts — all modal components use these helpers
const DAEMON_URL = import.meta.env.VITE_DAEMON_URL || 'http://localhost:8000';

// Store credentials in vault (called before activateBridge)
export async function saveBridgeCredentials(
  id: string, creds: Record<string, any>, token: string
): Promise<boolean> {
  const res = await fetch(`${DAEMON_URL}/api/channels/${id}/config`, {
    method: 'PUT',
    headers: { 'Authorization': `Bearer ${token}`, 'Content-Type': 'application/json' },
    credentials: 'include',
    body: JSON.stringify(creds),
  });
  return res.ok;
}

// Activate bridge adapter with stored credentials
export async function activateBridge(
  id: string, token: string
): Promise<{ connected: boolean; alias?: string; profileImg?: string; error?: string }> {
  const res = await fetch(`${DAEMON_URL}/api/channels/${id}/connect`, {
    method: 'POST',
    headers: { 'Authorization': `Bearer ${token}`, 'Content-Type': 'application/json' },
    credentials: 'include',
  });
  if (!res.ok) return { connected: false, error: await res.text() };
  return res.json();
}

Token Auto-Refresh Pattern — All OAuth Adapters
Add to backend/bridges/base.py and implement in every OAuth adapter
# In BridgeAdapter base class:
async def _get_valid_token(self) -> str:
    creds = await self.vault.retrieve_secret(f'channel_{self.bridge_id}')
    if time.time() < creds.get('expires_at', 0) - 300:  # 5-min buffer
        return creds['access_token']
    new_creds = await self._refresh_token(creds['refresh_token'])
    await self.vault.store_secret(f'channel_{self.bridge_id}', {**creds, **new_creds})
    return new_creds['access_token']

# In each OAuth adapter's send() and receive():
async def send(self, recipient: str, content: str, **kwargs):
    token = await self._get_valid_token()  # Always call this first
